# SeedGuard 地图种子隐藏 v1.0.1

阻止玩家用 SCP:SL 原版控制台指令 `seed` 查看本局真实地图种子，防止拿种子去地图查询网站提前获知设施布局。插件为 **SeedGuard.dll**，不依赖 Harmony，也不修改任何游戏方法。

## 工作原理

- 原版 `seed` 是客户端控制台的本地指令（`CommandSystem.Commands.Console.SeedCommand`），读取的是玩家客户端自己保存的 `SeedSynchronizer.Seed`。输入它不会向服务器发送任何消息，所以服务器**无法拦截这条指令，也无法知道谁输入了它**。
- 客户端保存的种子来自服务器下发的 `SeedSynchronizer.SeedMessage`。客户端必须用真实种子在本地生成设施布局，所以真实种子不能不发。
- 原版客户端收到种子消息时，如果地图已经生成，只会覆盖保存的种子，不会重建地图。SeedGuard 等玩家加载完地图并完成认证后，再补发一条显示用种子消息。此后该玩家输入 `seed` 只能看到 `Map seed is: 114514`（数字可配置）。
- 补发时机有严格限制：服务器本局地图已生成、不在换图或重启过程中、玩家连接已就绪且玩家对象已生成、已通过认证。每个连接每张地图只发一次，并与原版真实种子走同一条可靠通道，保证到达顺序在真实种子之后。
- 补发后向玩家控制台推送一行提示，默认“服务器禁止使用Seed指令”。客户端的 `seed` 输出格式由客户端写死为 `Map seed is: <整数>`，服务器只能决定这个数字，不能把它换成文字，所以文字提示通过控制台消息单独发送。

## 安装

运行环境：**SCP:SL 14.2.7 / EXILED 9.14.2**。

1. 停服，把 `SeedGuard.dll` 放入服务器的 `EXILED/Plugins/` 目录。
2. 启动服务器，确认日志出现 `[SeedGuard] v1.0.1 已启用`。
3. 按需修改配置中的 `seed_guard` 段（见下文），并给管理组添加权限 `seedguard.status`。
4. 进服后在控制台（`~` 键）输入 `seed`，应显示 `Map seed is: 114514`，控制台中还能看到“服务器禁止使用Seed指令”的提示。

从 v1.0.0 升级时，EXILED 会保留配置文件里已有的 `displayed_seed: 0`。如果要显示 114514，请把该项改为 114514 后重启。

启动时插件会核对游戏的客户端种子处理逻辑和所需的网络消息结构。如果游戏更新改变了这些逻辑，插件会拒绝启用并在日志中说明原因，而不是冒险让玩家客户端生成错误地图。

## 配置

```yaml
seed_guard:
  is_enabled: true
  debug: false
  # 玩家在控制台输入 seed 时显示的数字。客户端只能显示数字，无法显示文字；设为 0 可明确表示已隐藏（真实种子不可能是 0）。
  displayed_seed: 114514
  # 隐藏种子后推送到玩家控制台的提示，玩家输入 .seed 时也回复这句话；留空则不推送。
  notice: 服务器禁止使用Seed指令
  # 控制台提示颜色，例如 red、yellow、green、cyan、magenta、white。
  notice_color: red
  # 隐藏种子后延迟多少秒推送控制台提示（0–60）。
  notice_delay: 3
  # 检查新玩家的间隔秒数（0.05–5）。
  check_interval: 0.25
  # 是否为每名玩家记录一条“已隐藏种子”日志。
  log_each_player: false
```

`seed` 的输出格式由客户端固定为 `Map seed is: <整数>`，这里只能填整数，不能填文字。如果 `displayed_seed` 恰好等于本局真实种子，插件会改为显示 0。

## 指令

| 指令 | 使用位置 | 说明 |
| --- | --- | --- |
| `seedguard` / `seedguard status` | 远程管理、服务器控制台 | 显示保护状态、本局真实种子、各状态人数和 `.seed` 查询记录。权限 `seedguard.status` |
| `seedguard list` | 远程管理、服务器控制台 | 在状态之外逐个列出在线玩家的隐藏状态 |
| `sgd` | 同上 | `seedguard` 的别名 |
| `.seed` | 玩家客户端控制台 | 回复“服务器禁止使用Seed指令”，并在服务器日志中记录是谁查询的 |

## 能监控什么

- 原版 `seed` 在客户端本地执行，**服务器无法看到谁在什么时候输入了它**。
- 可以看到的是种子下发链路：哪些玩家已经被覆盖为显示用种子、哪些还在加载、哪些发送失败；每局结束时日志会汇总本局隐藏人数。
- 玩家输入 `.seed`（带点的写法会发往服务器）时，日志会记录玩家名称和 ID，`seedguard status` 中保留最近 10 条。
- 连续两局种子相同时日志会告警。这通常说明配置了固定 `map_seed`，或有插件固定了种子；此时地图布局每局不变，隐藏种子也挡不住玩家记住布局。

## 限制

- 只能挡住**原版客户端**的 `seed` 指令。修改过的客户端或抓包工具仍能读到连接时那条真实种子消息；客户端本身也掌握完整的地图布局。这些在服务器端无法根治。
- 从玩家客户端生成地图到收到显示用种子之间，约有一个网络往返的空窗，通常仍处在加载画面中。
- 原版客户端会用种子打乱 SCP-3114 同类语音台词的播放顺序。收到显示用种子的玩家听到的会是同类台词中的另一条，只影响听到哪一条，不影响玩法。
- 回合重启时原版客户端都会重新连接，插件按新连接处理。如果某个连接换图后没有重连（原版不会出现），为避免其客户端用显示用种子重建地图，本局不处理该连接，并在日志中告警。
- 地图生成被禁用（种子为 -1）时，客户端本来就不生成设施布局，插件不做处理。

## 构建

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

`build.ps1` 用 .NET SDK 自带的 Roslyn 编译器，以 `refs/` 中的游戏与框架程序集为引用，输出 `build/SeedGuard.dll`。`tests/run.ps1` 编译并运行回归程序和静态审计，需要 Mono 6.12 和 Unity 自带的 Mono.Cecil。

## 构建说明

- 编译依赖 SCP:SL 游戏程序集及 EXILED / LabAPI 等框架程序集（放在工作区 `refs/` 目录），这些第三方文件不随仓库分发。
- 各版本新增功能与修复内容见 [CHANGELOG.md](CHANGELOG.md) 及 GitHub Releases。
